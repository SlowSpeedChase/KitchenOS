# lib/ conventions

Library modules powering the KitchenOS pipeline. Each file should have a top-level docstring explaining its role — read that first when navigating an unfamiliar module.

## Conventions

- **Vault paths**: derive every recipe/meal-plan/meals path from `paths.py` helpers (`vault_root()`, `recipes_dir()`, `meal_plans_dir()`, `meals_dir()`). Never hardcode a vault path or join `~/KitchenOS/vault/...` directly. The vault location is overridable via the `KITCHENOS_VAULT` env var, and only `paths.py` honors it. `paths.py` calls `load_dotenv()` on import (override=False) so cron scripts (whose plists set no `EnvironmentVariables`) still resolve the configured vault — don't rely on entry-point scripts loading `.env` themselves for path resolution.
- **Controlled vocabularies** live in `normalizer.py` (recipe tags) and `inventory.py` (`CATEGORIES`, `LOCATIONS`, `SOURCES`). When adding a new tag-like field, add a `*_MAP` and route it through `normalize_field()` rather than letting raw AI output flow through.
- **Backups before destructive writes**: use **`backup.write_note(path, content)`** to write any recipe or meal-plan note. It snapshots whatever was there first, no-ops when the content is unchanged (so a corpus-wide sync neither spams `.history` nor churns the mtimes sidecar freshness checks read), and returns whether it wrote. The older `backup.create_backup()` + `write_text` pair is equivalent and still used in ~15 places, but it is a convention a new writer has to already know — and three didn't: `cook_history` (syncs into real recipes automatically), `import_crouton` (replaces a whole existing file, *My Notes* included) and `generate_meal_plan --force`. The vault is not in git, so a missed snapshot is unrecoverable. Backups live in a sibling `.history/` folder and auto-clean after 30 days.
  **Generated read-only views are the deliberate exception** — `Cook Now.md`, `Use It Up.md`, `Inventory.md`, the dashboards, `week_view`. They are rewritten from the DB on every relevant change and carry a do-not-edit banner, so a snapshot of one is noise, not safety.
- **Atomic JSON writes**: see `item_aliases.py` for the `tmp + replace` pattern. Use it for any small JSON sidecar that would corrupt if a write is interrupted (alias cache, task cache).
- **Sidecar caches**: keyed by `<basename>.<purpose>.json` next to the source file (e.g. `2026-W03.tasks.json` next to `2026-W03.md`). Freshness check: `sidecar_mtime >= source_mtime`.
- **DB access**: all SQLite access goes through `inventory_db.py` — never open `sqlite3` connections elsewhere. Tests point the DB at a temp file via the `KITCHENOS_DB` env var (`tmp_db` fixture in `tests/conftest.py`).
